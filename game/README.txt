这个目录放真实游戏客户端，不是仿真器，也不是逆向还原的 Rust 端口。项目后续的感知、校准、试射和对局都以这个客户端为准。

运行

需要 Java 8 或更高版本。当前机器验证的是 Java 1.8.0_503。

    cd game
    java -jar graphwar.jar

或者从项目根目录运行：

    bash game/run.sh

启动后会出现标题为 Graphwar 的 AWT 窗口。屏幕读取只截取这个窗口的客户区，不读内存，不注入进程，不修改 jar。

屏幕读取假设

窗口客户区里包含坐标区和下方控制面板。坐标区是白底矩形，宽高比接近 50 比 30，常见尺寸是 770 乘 450 像素，左上角在客户区内的偏移量因窗口装饰和缩放而异。感知层每次都以实际检测到的矩形为准，不写死偏移。

障碍是黑色圆，士兵是鲜艳的彩色球，名字牌是浅色文字。当前 vendored 检测器就是按这套视觉规则写的。

函数图像的原点

对局中观察到：发射时函数图像以开火士兵的位置为原点绘制，不是以世界坐标原点为原点。也就是说，表达式里的 x 是相对射手的水平距离，曲线跟着射手走。这一点还要用试射确认细节（入参 x 是射手相对还是世界坐标、累加常数是否被抵消、起点取士兵中心还是边缘），确认前求解器一律按射手相对坐标实现，并在配置里保留开关。

绘图区里的黑色十字也要单独确认：它可能是固定的世界原点网格，也可能是跟着当前射手移动的坐标轴。截两张不同射手的画面比较十字位置即可判定。如果它会移动，感知就不能拿它当世界坐标锚点。

使用范围

只在自己创建的房间、离线模式或与内置机器人对战中运行。不使用公开服务器，不参与排位，不影响其他玩家。默认由人确认后开火。

为什么不用本地 Rust 端口

graphwar/ 下的 Rust 端口是第三方逆向还原，界面主题、渲染方式和坐标映射都和真实客户端不同。它只能作为阅读参考或开发期的快速仿真器，不能作为感知验收和真实对局依据。
